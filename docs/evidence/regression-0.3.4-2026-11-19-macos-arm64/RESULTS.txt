The new scenario: node:zec:zec-maker-early-claim:TakerSellsLez

It is new in this commit (TakerSellsLez only). With the Maker's Zcash route cut, the Taker
locks LEZ and the Maker never funds Zcash; the harness then searches the Maker's files for
the swap's preimage and its digest, makes a control search over the Taker's files, and has
the Maker's own LEZ signer submit two claims on the Taker's escrow with the test-only tool
lez-v02-escrow-claim-probe (a zero preimage; the digest as the preimage); the Maker Node is
stopped, and the Taker refunds its LEZ at the refund time.

Its complete output is in two places:
- early-claim-first-runs/: the first runs of the scenario on any stack, once per lane, on
  the run's chain before the full run (lane 1 alone, then lanes 2 and 3 together):
  lane 1 547 s, lane 2 537 s, lane 3 537 s, all passed. Each log
  (node-zec-zec-maker-early-claim-TakerSellsLez-lane<k>.log) and summary
  (lane<k>/zec-maker-early-claim.json).
- logs/node-zec-zec-maker-early-claim-TakerSellsLez-1.log: its run inside the full run (lane
  3, 540 s, passed), with the summary e2e/zec-maker-early-claim.json.

In all four runs: the probe tool runs in the Maker image at
/usr/local/bin/lez-v02-escrow-claim-probe; the Maker's signer is the escrow's claimant
("signer_is_claimant": true); the on-chain swap id (derive_lez_swap_id_v1) and the escrow
program resolve to the funded escrow; the search lists every file it read under the Maker's
/var/lib/lez/maker, /var/lib/lez/zec and /run/lez/maker and finds the digest (raw, in 4 files
each run) and no form of the preimage (raw, hex, HEX, base64: 0 files), while the control
search finds the preimage in the Taker's claim-preimage.key; both claims are accepted by the
sequencer and never included, the escrow staying Funded with its custody unchanged and the
Maker's LEZ unchanged (the probe's JSON before and after each attempt is in the log); the
Taker's refund lands and both Nodes end refunded; the Zcash funding outpoint stays unspent.
The preimage itself is never printed: the harness reads it from the Taker's file and logs its
SHA-256 only.
